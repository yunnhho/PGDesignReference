# 4회차 — 문제 → 해결

새 Sonnet 에이전트 4개로 진행했고, 프롬프트는 이전 회차와 같다. 사용량 한도로 A·C·D가 중간에 멈춰서, 한도가 풀린 13시에 같은 에이전트로 이어서 끝냈다. 4개 모두 빌드 경고 0개, render `점검 0건`이다.

## 보완 사항이 줄었는가

- 회차별 보완 사항 수: 1회차 13건 → 2회차 13건 → 3회차 9건 → 4회차 6건.
- 4회차에는 PNG에서 규칙 위반이 2건만 보였다.
  - A: "28.4 s (상한 28)"처럼 기준 문구의 자리수가 측정값과 다르다.
  - C: 입력 표가 읽기 전용 칸이 선택된 채로 시작한다.
- 나머지는 에이전트가 "짐작했다"고 보고한 애매한 규칙이다.
- 이전 회차에 지적한 것이 다시 나오지 않았다: 선택 타일, 경계값, 램프 열 제목, 제목 불일치, 진행률 강조, 헤더 순서, 기준값 보고.

## 문제와 처리

| # | 문제 (출처) | 처리 |
|---|---|---|
| 1 | 측정값의 상한·경고값을 시간 설정(정수)으로 볼지 측정값(`0.0`)으로 볼지 모호하다. 그래서 "28.4 s (상한 28)"처럼 자리수가 섞였다 (A) | 4-1 소수 자리에 명시: 측정값과 비교하는 상·하한·경고값은 측정값 자리수("상한 28.0 s")로 쓴다. 정수는 사람이 넣는 목표·설정값만이다 |
| 2 | 정지 설비가 읽은 값이 이상일 때 타일을 알람으로 할지 모호하다 (A) | 명시: 그 값은 카드·셀에서만 판정하고, 타일·행·헤더는 공정 상태(정지·대기)를 따른다 |
| 3 | 입력 표의 첫 열이 읽기 전용이면 그 칸이 선택된 채 시작한다 (C, 1회차부터 매번) | **코드**: `ApcGrid`에서 `ClearInitialSelection = false`인 입력 표는 시작 칸이 읽기 전용 열이면 같은 행의 첫 입력 칸으로 옮긴다. 점검을 추가했다 |
| 4 | 굵은 글꼴 호출법이 SKILL.md에 없어서 빌드 오류가 났다 (B) | 4-1 글꼴 항목에 `ApcTheme.GetFont(FontStyle.Bold)`를 추가했다 |
| 5 | 표 세로 스크롤바 안내가 "참고"처럼 적혀 있지만 실제로는 "점검"으로 나온다 (A) | 샘플 행 수 설명을 "참고 줄 … / 점검 줄 …"로 구분했다 |
| 6 | MSBuild `logfile`을 상위 경로로 주면 드라이브 루트로 풀려 정리가 막힌다 (C) | 7단계 빌드에 "프로젝트 폴더 안 상대 경로" 한 줄을 추가했다 |

## 규칙으로 남기지 않은 것 (더 안전하다고 판단)

- **단위 소수 자리 (B·C·D):** Pa/s·mΩ·nA·개/ft³이 4-1 표에 없다. 확정된 단위 표이고, 없는 단위는 묻는다는 규칙을 유지한다. 시연에서는 질문을 금지했기 때문에 생긴 일이다. 4회 모두 에이전트가 "정한 기준값"으로 보고해서 사용자가 고칠 수 있었다.
- **질문 금지 상황의 기본값 (B·D):** 실제 사용에서는 질문할 수 있다. 기본값을 만들면 묻지 않고 넘어가는 쪽으로 기울 위험이 있다.
- **`SectionTitle` 이름이 겹치는 문제, 판정 화면 NG의 알람바 표시 (B):** 4a·4b가 각각 설명하고 있고, `JudgeView` 관례로 충분하다.
- **dialog를 여는 버튼 위치, 값 없는 그래프, 정지·대기를 따로 세는 조건 (A):** 화면마다 판단할 일이다. 결과도 규칙에 맞았다.
- **카드와 표 중 무엇을 쓸지, `Selected`와 상세 dialog 중 무엇이 우선인지, 오류 사유 문구 (D):** 규칙이 이미 조건부로 적혀 있다("아래 카드가 그 설비를 보여 주는 화면은"). 판단할 여지를 두는 편이 안전하다.
- **요구서에 없는 기준을 설정 dialog에 넣을지, 통신 끊김 구역의 그래프, 열 제목이 긴 열의 폭 (C):** 화면마다 판단할 일이고, render 점검을 통과했다.
