# 5회차 — 문제 → 해결 (루프 마지막 회차)

5회차는 새 Sonnet 에이전트 4개로, 이전 회차와 같은 프롬프트로 진행했다. 4개 모두 빌드 경고 0개, render `점검 0건`이다.

## 수렴 상태

| 회차 | 보완 반영 건수 | PNG에서 보인 규칙 위반 |
|---|---|---|
| 1 | 13 | 다수 (경계값·선택 표시·3중 강조·색만 있는 램프 등) |
| 2 | 13 | 몇 건 (복귀 순서·규칙 설명 문구) |
| 3 | 9 | 2건 (진행률 초록·제목 불일치) |
| 4 | 6 | 2건 (기준값 자리수·입력 표 시작 칸) |
| 5 | 4 | 1건 (C: 정지 구역 빨간 셀이 헤더 알람 수와 어긋남) |

이전 회차 지적은 다시 나오지 않았다. 4회차 반영 사항(기준값 "상한 28.0", 입력 표 시작 칸)과 3회차 반영 사항(멈춘 진행률 회색)이 모두 지켜졌다.

## 문제와 처리

| # | 문제 (출처) | 처리 |
|---|---|---|
| 1 | 정지 구역의 읽은 값이 빨간 셀로 보이는데 헤더 알람 수에는 없다 (C, PNG로 확인). 정지 설비의 정상 값 카드를 초록으로 둘지도 모호하다 (A) | 4회차 규칙을 바꿨다. 정지·대기 설비가 읽은 값은 **판정하지 않는다**. 값만 보이고 카드·셀은 `Stop`(기본 글자색)이며, 상태는 공정 상태를 따른다. "빨간 셀이 보이는데 헤더 알람 수에 없으면 틀린 것"이라는 문장을 함께 넣었다 |
| 2 | 경고를 읽고도 heredoc을 쓰다 실패했다 (A·B, 누적 다섯 차례) | 경고를 SKILL.md 맨 위 인용 블록으로 올렸다. 2단계의 긴 문단은 "실패했으면 전부 Write로 다시"만 남겨 중복을 없앴다 |
| 3 | 판정 화면 헤더의 "NG 발생"이 최근 판정 기준인지 오늘 누적 기준인지 모호하다 (B) | "가장 최근 판정이 NG일 때"로 명시했다 (`JudgeView`와 같음) |
| 4 | 완료 채널의 진행률 카드를 `Run`으로 할지 `Stop`으로 할지 모호하다 (D) | "정상 완료한 설비의 진행률·최종값은 `Run`"으로 명시했다 |
| 5 | 헤더 요약 순서에 "통신 끊김"이 없다 (C) | 순서를 "(정상) → 알람 → 경고 → 정지 → 대기 → 통신 끊김"으로 명시했다 |

## 남은 피드백 — 규칙으로 남기지 않는 편이 안전한 것

- **단위 소수 자리 (mΩ·nA·Pa/s·회·개/ft³):** 사용자가 확정한 단위 표다. 표에 없으면 묻는다는 규칙을 유지한다. 시연에서는 질문을 막아 두어 생긴 문제이고, 에이전트들이 "정한 기준값"으로 보고하는 규칙(2회차)이 대신 받쳐 준다.
- **레시피 저장값과 판정 기준 연결, 입력 검증 Alert 문구, 비밀번호 검증 (A·B·C):** 실제 데이터를 연결할 때 정할 일이다.
- **dialog 여는 버튼·제목+버튼 줄의 위치, 고정 열 폭 값, 그래프 X축 이름표, 그래프 2개 나란히 배치, 숫자칸 옆 안내 문구 (A·C):** 화면마다 판단할 배치다. 모두 render `점검 0건`이었고 PNG에도 문제가 없었다. 규칙으로 정하면 다른 화면에서 맞지 않을 수 있다.
- **타일 공정 상태 문구로 "가동"과 "알람" 중 무엇을 쓸지 (A):** 규칙("공정 상태 · 사유")대로 하면 된다. 템플릿의 "알람 · …"도 상태 문구로 읽힌다. 하나로 강제할 근거가 없다.
- **오류 코드 카드 Status, 불량 표 램프 열 생략, `Selected` 적용 범위, 타일에서 챔버 값 제외 (D):** 기존 규칙의 조건문으로 판단할 수 있고, 결과도 규칙에 맞았다.
- **글 열 위 제목 정렬 (C):** 사용자가 확정한 기준(헤더 포함 가운데)이다.
- **집계 카드의 작은 글자 (B):** 컨트롤이 카드 높이에 따라 글자 크기를 정하는 동작이다. 읽을 수 있고, 카드를 키우면 표 행 수가 줄어든다.

→ **루프를 끝낸다.** 상한 5회에 도달했고, 남은 것은 모두 위와 같이 "규칙으로 남기지 않는 편이 안전한 사항"이다.

- `build.sh` 결과는 `ALL PASSED (237)`이다. 스킬을 재설치했다.
- 4-1 전체를 다시 읽어 모순이 없는지 확인했다.
  - "카드 Status"와 "타일 상태 = 나쁜 쪽" 규칙은 정지·대기 설비만 예외라 충돌하지 않는다.
  - 값 없음 규칙과 정지 설비 규칙의 경계도 맞는다.
