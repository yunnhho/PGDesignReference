# 2회차 — 문제 → 해결

2회차 시연은 새 Sonnet 에이전트 4개(A·B·C·D)로 했다. 프롬프트는 1회차와 같다. 4개 모두 빌드 경고 0개, render `점검 0건`이다.

## 1회차 보완 반영 확인

- A: 선택 타일이 표시된다(`Selected`). 이력의 "초과"는 상한보다 큰 값에만 쓰였다.
- B: 상한과 같은 5.0이 OK로 판정된다.
- C: 표 높이를 `HeightFor(HeightForRows(8))`로 맞췄다. 1회차의 빈 줄과 중복 문구가 없다.
- D: 값이 없을 때 판정하지 않는다. 진행률 카드 3중 강조와 색만 있는 램프 표가 없어졌다.

## 규칙으로 남기지 않은 것 (더 안전하다고 판단)

- 진행률 %·mΩ·nA의 소수 자리(D): 기존 규칙대로 사용자에게 묻는다. 진행률을 정수로 할지는 사용자가 정할 일이다.
- 스캔 입력이 없는 판정 화면에서 템플릿의 무엇을 뺄지(B): 화면마다 다르게 판단할 일이다. 이번 결과도 문제가 없었다.
- 판정판 SubText에 쓸 내용(B): 화면마다 다르게 판단할 일이다.
- 관리자 비밀번호 검증, 알람바 지우기 API(B·C): 실제 데이터 연결 범위다. 1회차와 같은 판단이다.
- 이탈 구역 강조 방식(C): 지금 방식(램프 + 문구 + 셀 글자색)으로 충분하다.
- 타일과 겹치는 표에서 램프 열을 뺀 것(D): 상태가 글 열로 읽히므로 4c 규칙에 맞다.

## 코드·설정 점검

- `build.sh` 결과 `ALL PASSED (233)`이다.
- render 점검을 새로 넣은 뒤 `FailureAnalysisView` 템플릿에서 오탐이 1건 나왔다. 묶음 머리글 표의 하위 열 반복이었고, 램프 열 중복만 보도록 좁혀 해결했다.
- `APC.UI`의 public API는 바뀌지 않았다(도구 점검만 바뀜). 그래서 버전은 1.9.0.0을 유지한다.
- 스킬을 재설치했고, 설치본에 새 규칙이 반영된 것을 확인했다.
